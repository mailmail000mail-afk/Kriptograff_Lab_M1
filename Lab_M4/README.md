## Вычисление хеша

```text
cryptocore dgst --algorithm {sha256,sha3-256}
                --input INPUT_FILE [--output OUTPUT_FILE]
```

Параметры:

- `--algorithm` — `sha256` или `sha3-256`;
- `--input` — путь к файлу; значение `-` означает стандартный ввод;
- `--output` — необязательный файл для результата.

Команда `dgst` не принимает `--key`, `--mode`, `--encrypt`, `--decrypt` и `--iv`, потому что хеширование не является шифрованием.

### Примеры

```powershell
cryptocore dgst --algorithm sha256 --input document.pdf
cryptocore dgst --algorithm sha3-256 --input archive.bin
cryptocore dgst --algorithm sha256 --input image.png --output image.sha256
cmd /c "type message.txt | cryptocore dgst --algorithm sha3-256 --input -"
```

Без `--output` программа печатает ровно одну строку в формате утилит `*sum`:

```text
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad example.txt
```

Хеш записывается строчными шестнадцатеричными символами. С `--output` эта же строка записывается в файл, а стандартный вывод остаётся пустым.

## Как работают реализации

### SHA-256

`sha256.py` реализует конструкцию Меркла — Дамгарда:

1. сообщение дополняется битом `1`, нулями и 64-битной длиной;
2. данные обрабатываются блоками по 512 бит;
3. для каждого блока строится расписание из 64 слов;
4. выполняются 64 раунда с константами и функциями из FIPS 180-4;
5. восемь 32-битных слов образуют 256-битный результат.

### SHA3-256

`sha3_256.py` реализует sponge-конструкцию Keccak:

- состояние — 1600 бит;
- скорость `rate` — 1088 бит, стойкость `capacity` — 512 бит;
- используется дополнение SHA-3 с доменным байтом `0x06`;
- перестановка Keccak-f[1600] содержит 24 раунда Theta, Rho, Pi, Chi и Iota;
- после поглощения данных из состояния извлекаются 256 бит результата.

Файл читается в бинарном режиме блоками по 8192 байта в `hashing.py`. Поэтому объём оперативной памяти не зависит от размера файла. Пустые, текстовые и бинарные файлы обрабатываются одинаково.

## Свойства безопасности

Обе функции возвращают 256-битный хеш. Для идеальной 256-битной функции ожидаемая сложность поиска коллизии составляет около `2^128`, а нахождения прообраза — около `2^256` операций.

SHA-256 широко применяется для контроля целостности, но его конструкцию нельзя напрямую использовать как MAC вида `SHA256(secret || message)` из-за расширения длины. Для аутентификации нужен HMAC. SHA3-256 имеет sponge-конструкцию и не обладает классической уязвимостью расширения длины SHA-2.

Хеш сам по себе не подтверждает автора файла и не защищает от злоумышленника, который может заменить одновременно файл и опубликованный хеш. Для такой задачи нужна цифровая подпись или доверенный канал. Обычные SHA-256/SHA3-256 также не подходят для хранения паролей: для паролей применяют специальные медленные функции с солью.

## Шифрование из прошлых спринтов

```text
cryptocore --algorithm aes --mode {ecb,cbc,cfb,ofb,ctr}
           (--encrypt | --decrypt) [--key KEY] [--iv IV]
           --input INPUT [--output OUTPUT]
```

- `--key` — ключ AES-128 из 32 hex-символов;
- при шифровании ключ может быть создан системным CSPRNG автоматически;
- при расшифровании ключ обязателен;
- `--iv` разрешён только при расшифровании CBC, CFB, OFB и CTR;
- без `--output` добавляется суффикс `.enc` или `.dec`.

В режимах CBC, CFB, OFB и CTR автоматически созданный 16-байтный IV записывается перед шифротекстом. ECB и CBC используют PKCS#7. Эти режимы не обеспечивают аутентификацию; в прикладной системе предпочтителен AEAD, например AES-GCM.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Набор из 51 теста проверяет:

- известные ответы NIST для SHA-256 и SHA3-256, включая пустой ввод и миллион символов `a`;
- обновление хеша частями и границы внутренних блоков;
- совпадение обеих реализаций с OpenSSL;
- точный формат CLI, стандартный ввод, выходной файл и сообщения об ошибках;
- потоковое чтение виртуального входа размером больше 1 ГиБ блоками по 8192 байта;
- лавинный эффект при изменении одного бита;
- все проверки AES, режимов, IV и CSPRNG из Sprint 1–3.
