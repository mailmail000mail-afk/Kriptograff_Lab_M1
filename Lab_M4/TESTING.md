## Контрольный запуск

Команда из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

## Совместимость с OpenSSL

Тест `test_both_algorithms_match_openssl` создаёт бинарный файл и сравнивает результат CryptoCore с командами:

```powershell
openssl dgst -sha256 interop.bin
openssl dgst -sha3-256 interop.bin
```

Обе суммы совпали. Прежние тесты совместимости AES также выполнены в обоих направлениях: CryptoCore → OpenSSL и OpenSSL → CryptoCore для CBC, CFB-128, OFB и CTR.

## Потоковое чтение большого входа

`test_virtual_stream_larger_than_one_gibibyte_is_chunked` передаёт функции чтения виртуальный бинарный поток размером `1 073 741 947` байт, то есть 1 ГиБ + 123 байта. Объект ведёт себя как большой файл, но не занимает гигабайт на диске и не хранит его в памяти.

Тест подтверждает, что:

- обработан весь заявленный объём;
- ни один запрос чтения не превышает 8192 байта;
- данные поступают в хеш-функцию последовательно;
- объём используемой памяти не растёт вместе с размером входа.

Корректность самих алгоритмов отдельно проверяется известными ответами, миллионом символов и реальными бинарными файлами.

## Лавинный эффект

В сообщении `CryptoCore avalanche effect test message` изменён один бит. Число отличающихся битов результата:

| Алгоритм | Изменилось бит из 256 |  Доля  |
|----------|----------------------:|-------:|
|  SHA-256 |          122          | 47,66% |
| SHA3-256 |          131          | 51,17% |

Автоматический тест принимает диапазон от 100 до 156 бит. Оба результата близки к ожидаемым 50%.

## Проверки командной строки

Тестами подтверждено следующее:

- вывод имеет вид `HASH_VALUE INPUT_FILE_PATH`;
- hex-строка записана в нижнем регистре;
- `--output` получает ту же строку, а `stdout` остаётся пустым;
- `--input -` читает стандартный ввод;
- отсутствующий файл даёт понятное сообщение и код возврата 1;
- `dgst` отклоняет параметры шифрования, например `--key`;
- пустой и бинарный ввод обрабатываются без специальных исключений.
