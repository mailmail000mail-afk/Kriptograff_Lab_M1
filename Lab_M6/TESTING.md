## Контрольный запуск

Из корня проекта выполнена команда:

```powershell
python -m unittest discover -s tests -v
```

Результат: **85 тестов успешно**, ошибок и пропусков нет. Набор включает 67 проверок Sprint 1-5 и 18 новых тестов GCM и Encrypt-then-MAC.

## Официальные примеры NIST

Реализация проверена по первым пяти 128-битным примерам из документа [GCM Mode for Authentication and Confidentiality].

Во всех примерах используются ключ `feffe9928665731c6d6a8f9467308308` и nonce `cafebabefacedbaddecaf888`.

| Пример | AAD | Открытый текст | Тег |
|---:|---:|---:|---|
| 1 | 0 байт | 0 байт | `3247184b3c4f69a44dbcd22887bbb418` |
| 2 | 0 байт | 64 байта | `4d5c2af327cd64a62cf35abd2ba6fab4` |
| 3 | 64 байта | 0 байт | `5f91d77123ef5eb9997913849b8dc1e9` |
| 4 | 64 байта | 64 байта | `64c0232904af398a5b67c10b53a5024d` |
| 5 | 20 байт | 60 байт | `f07c2528eea2fca1211f905e1b6a881b` |

Для примеров с сообщением проверены и шифротекст, и полный 16-байтный тег. Затем полученные данные расшифрованы обратно.

## Сверка с независимой реализацией

Тесты используют `Crypto.Cipher.AES.MODE_GCM` только как эталон. Проверены nonce длиной 8, 12 и 20 байт, а также сообщения длиной 0, 1, 17 и 73 байта с разными длинами AAD.

Шифротекст и тег CryptoCore побайтно совпали с эталоном. Это отдельно подтверждает ветвь GHASH для nonce нестандартной длины.

## Проверка отказа

Автоматические сценарии изменяют:

- AAD;
- один бит шифротекста;
- один бит тега;
- nonce в схеме Encrypt-then-MAC.

Каждый вариант вызывает `AuthenticationError`. Командная строка возвращает код 1, печатает понятное сообщение и не создаёт выходной файл. Расшифрование запускается только после успешной проверки тега.

## Формат файла и AAD

Командный тест подтверждает формат:

```text
12-byte nonce || ciphertext || 16-byte tag
```

Проверены непустой AAD, пустой AAD по умолчанию, явный nonce для вектора NIST и передача nonce отдельно при расшифровании `ciphertext || tag`.

Некорректный hex AAD, nonce неверной длины и `--aad` с режимом CTR отклоняются парсером до чтения файла.

## Случайные nonce

Созданы 1000 объектов GCM без явно заданного nonce. Все 1000 значений длиной 12 байт оказались уникальными. Источником служит системный CSPRNG из Sprint 3.

## Большой AAD

Потоковый интерфейс GHASH проверен на виртуальном AAD размером `1 073 742 145` байт, то есть 1 ГиБ + 321 байт. Одно чтение не превышает 8192 байта. Тест не создаёт гигабайтный файл и не выделяет гигабайт памяти.

Корректность потокового состояния дополнительно проверена: AAD и шифротекст, переданные фрагментами разного размера, дают тот же GHASH, что и цельные значения.

## Encrypt-then-MAC

Составная схема выполняет AES-CTR и затем HMAC-SHA-256 от `IV || ciphertext || AAD`. Ключ AES и ключ HMAC выводятся из мастер-ключа с разными метками.

Проверены полный цикл, длина формата, разные производные ключи, случайный IV и отказ при изменении IV, шифротекста, тега или AAD.

## Проверка OpenSSL

Требование предлагает команду `openssl enc -aes-128-gcm`. Локально проверен OpenSSL 3.5.6, который отвечает:

```text
enc: AEAD ciphers not supported
```

Это ожидаемое ограничение: [документация OpenSSL enc] прямо сообщает, что команда не поддерживает GCM и CCM. Поэтому вместо фиктивного теста `enc` используются официальные значения NIST и независимая библиотечная реализация GCM.

## Проверка файла задания

Для файла `m6_html.pdf` размером 66 274 байта использованы:

```text
key   = 00112233445566778899aabbccddeeff
nonce = 00112233445566778899aabb
aad   = 6d365f68746d6c2e706466
```

AAD является hex-представлением строки `m6_html.pdf`. Зашифрованный файл имеет размер 66 302 байта, то есть исходный размер плюс 12-байтный nonce и 16-байтный тег.

SHA-256 исходного и восстановленного файла совпал:

```text
3db6f9910f02409b87422fcb09fce0d3178d02e62ce57ea06e5b12e50e6a8e99
```

Расшифрование с AAD `00` вернуло код 1 и не создало выходной файл.

## Сохранение прежних функций

Все тесты AES-ECB/CBC/CFB/OFB/CTR, CSPRNG, SHA-256, SHA3-256 и HMAC-SHA-256 по-прежнему проходят. Изменение парсера не нарушило прежние правила для 16-байтного IV и команды `dgst`.
