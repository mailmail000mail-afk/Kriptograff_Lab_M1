# Проверка CryptoCore Sprint 3

## Автоматические тесты проекта

Команда:

```powershell
python -m unittest discover -s tests -v
```

Результат контрольного запуска: **36 тестов успешно**, пропусков и ошибок нет. В том числе выполнены два теста совместимости с OpenSSL: CryptoCore → OpenSSL и OpenSSL → CryptoCore для CBC, CFB-128, OFB и CTR.

Отдельно проверяются:

- шифрование без `--key`, извлечение напечатанного ключа и обратное расшифрование;
- единственный вывод метки `Generated random key:`;
- обязательность `--key` при расшифровании;
- применение `generate_random_bytes(16)` к ключу и IV;
- уникальность 1000 последовательно созданных ключей;
- доля единичных битов в 1000 ключах в диапазоне 45–55%;
- ошибки системного CSPRNG и очевидно слабые пользовательские ключи;
- все тесты Sprint 1 и Sprint 2.

## Официальный NIST STS 2.1.2

Настройки запуска:

| Параметр | Значение |
|---|---|
| Длина одной последовательности | 1 000 000 бит |
| Число последовательностей | 8 |
| Формат файла | Binary |
| Набор тестов | Все 15 |
| Уровень значимости | α = 0,01 |
| Параметры тестов | По умолчанию NIST STS 2.1.2 |

Итог: выполнены Frequency, Block Frequency, Cumulative Sums, Runs, Longest Run, Rank, FFT, Non-overlapping Template, Overlapping Template, Universal, Approximate Entropy, Random Excursions, Random Excursions Variant, Serial и Linear Complexity. Из 1504 индивидуальных результатов **1455 имеют p-value ≥ 0,01 (96,742%)**. Из 188 строк итогового отчёта **187 достигли минимальной доли прошедших последовательностей**. Одна из 148 подсерий Non-overlapping Template получила 6/8 при требуемом для этой выборки минимуме 7/8. Таким образом, требование о прохождении подавляющего большинства тестов выполнено; единичное отклонение при множественном тестировании не является основанием считать системный CSPRNG непригодным.

При восьми последовательностях программа выводит `----` для проверки равномерности распределения p-value: объёма недостаточно для десяти интервалов этой метапроверки. Поэтому в этом запуске интерпретируется доля прошедших последовательностей.

## Как повторить NIST STS

1. Установить CryptoCore и создать выборку:

   ```powershell
   python scripts/generate_nist_data.py --size-mib 10 --output nist_test_data.bin
   ```

2. Скачать NIST STS 2.1.2 с официальной страницы NIST и распаковать архив.

3. Собрать программу. В Linux/WSL из каталога `sts-2.1.2` выполнить `make`. В Developer Command Prompt for Visual Studio допускается собрать исходники командой:

   ```text
   cl /O2 /Iinclude src\*.c /Fe:assess.exe
   ```

4. Запустить `./assess 1000000` (Linux/WSL) или `assess.exe 1000000` (Windows).

5. В меню выбрать `Input File`, указать `nist_test_data.bin`, выбрать все тесты, сохранить параметры по умолчанию, задать число 1 000 000-битных последовательностей, помещающихся в файле, и выбрать `Binary`.

6. Открыть `experiments/AlgorithmTesting/finalAnalysisReport.txt`. Индивидуальная последовательность проходит тест при p-value ≥ 0,01. Для набора последовательностей также проверяется допустимая доля прохождения, которую программа печатает внизу отчёта.

NIST подчёркивает, что статистическое тестирование является первым шагом оценки генератора и не заменяет анализ его конструкции. В CryptoCore криптографическое основание даёт системный CSPRNG, доступный через `os.urandom`.

## Проверка реального файла

Для каждого из режимов ECB, CBC, CFB-128, OFB и CTR шифрование запускалось без `--key`, ключ извлекался из единственной информационной строки, после чего файл расшифровывался. SHA-256 исходного и всех пяти восстановленных файлов совпал:

```text
a6294b9ff8093c678b96ac0128fb9db195f341e570ca8fbb8fde2edf5e41a686
```

В каждом зашифрованном файле отдельно проверено отсутствие 16-байтного ключа. Для CBC, CFB, OFB и CTR первые 16 байт являются IV; ключ в файл не включается.
