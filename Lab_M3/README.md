## Синтаксис командной строки

```text
cryptocore --algorithm aes --mode {ecb,cbc,cfb,ofb,ctr}
           (--encrypt | --decrypt) [--key KEY] [--iv IV]
           --input INPUT [--output OUTPUT]
```

- `--key` — 16-байтный ключ AES-128 в виде 32 hex-символов.
- При шифровании `--key` необязателен: без него создаётся новый случайный ключ.
- При расшифровании `--key` обязателен. Ключ нельзя восстановить из шифротекста.
- `--iv` разрешён только при расшифровании в CBC, CFB, OFB и CTR.
- Если `--output` не задан, к имени входного файла добавляется `.enc` или `.dec`.

### Автоматически созданный ключ

```powershell
cryptocore --algorithm aes --mode ctr --encrypt --input plaintext.txt --output ciphertext.bin
```

Пример вывода (значение при каждом запуске новое):

```text
[INFO] Generated random key: 7c8bf5d01a2e34769948c0fe1d68a5b3
Шифрование завершено. Результат: ciphertext.bin
```

Строка с ключом выводится в стандартный поток ровно один раз. Сохраните 32 hex-символа в надёжном месте: программа не записывает ключ ни в шифротекст, ни в отдельный файл.

```powershell
cryptocore --algorithm aes --mode ctr --decrypt --key 7c8bf5d01a2e34769948c0fe1d68a5b3 --input ciphertext.bin --output restored.txt
```

### Заданный пользователем ключ

```powershell
cryptocore --algorithm aes --mode cbc --encrypt --key 00112233445566778899aabbccddeeff --input plaintext.txt --output ciphertext.bin
```

Такой ключ используется без замены. Для очевидно слабых шаблонов (например, все нули или последовательность `00 01 ... 0f`) программа выводит предупреждение в `stderr`, но не прерывает учебный эксперимент.

## CSPRNG и свойства безопасности

Функция `generate_random_bytes(num_bytes: int) -> bytes` находится в `src/cryptocore/csprng.py`. Она обращается только к `os.urandom`, то есть получает данные от криптографического генератора операционной системы. Модуль `random` не используется.

Один и тот же интерфейс CSPRNG применяется для:

- автоматически создаваемых 16-байтных ключей AES-128;
- каждого нового 16-байтного IV в CBC, CFB, OFB и CTR.

Свойства, на которые опирается проект: непредсказуемость без знания состояния системного генератора, высокая энтропия и практическая невозможность восстановить предыдущие значения по наблюдаемым. Статистические тесты подтверждают отсутствие обнаруженных закономерностей в конкретной выборке, но сами по себе не доказывают криптографическую стойкость.

## Формат данных и IV

| Режим | Дополнение | Формат файла CryptoCore |
|---|---|---|
| ECB | PKCS#7 | `<шифротекст>` |
| CBC | PKCS#7 | `<16-байтный IV><шифротекст>` |
| CFB | Нет | `<16-байтный IV><шифротекст>` |
| OFB | Нет | `<16-байтный IV><шифротекст>` |
| CTR | Нет | `<16-байтный IV><шифротекст>` |

При расшифровании без `--iv` первые 16 байт не-ECB-файла считаются IV. При явном `--iv` входной файл должен содержать только шифротекст — это удобно для совместимости с OpenSSL. Поведение IV не изменено относительно Sprint 2.
